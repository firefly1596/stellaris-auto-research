# Stellaris Auto Research

群星（Stellaris）自动科研接管 MOD —— 让自动科研按你的配置挑科技，跟你会手动选的一样。

> **游戏版本**：Stellaris 4.5.4 (Cygnus)
> **最后更新**：2026-11-20

---

## 快速开始（3 步）

### 0. 先装注入器（如果还没装）

本项目是一个 DLL，需要靠注入器把它加载进游戏进程：

**[Stellaris-Mod-Injector](https://github.com/MyresMkG/Stellaris-Mod-Injector/releases)**

下载发行版，挑一个代理 DLL（`dxgi` / `d3d11` / `d3dcompiler_47` / `version` / `winmm`，任选一个）复制到游戏根目录，和 `stellaris.exe` 同级：

```
Stellaris\
├── stellaris.exe
└── dxgi.dll          ← 从发行版复制的代理 DLL
```

### 1. 建目录，放 DLL

```
Stellaris\
└── injected_mods\
    └── auto_research\                 ← 新建这个文件夹
        └── auto_research.dll          ← 放这里
```

> **必须放在 `injected_mods` 的子目录里** —— 注入器只扫一层子目录，根目录和更深层都不认。

### 2. 启动游戏，让它生成配置文件

第一次启动后，DLL 会在**自己所在目录**自动创建：

```
Stellaris\injected_mods\auto_research\
    ├── auto_research.dll            ← 你放的
    ├── auto_research_weights.txt    ← 自动生成（配置）
    └── auto_research.log            ← 自动生成（日志）
```

### 3. 改配置，把 `@mode` 改成 `take`

打开 `auto_research_weights.txt`，把这一行：

```ini
@mode = observe
```

改成：

```ini
@mode = take
```

**保存即可，不用重启游戏**（热重载）。

## 配置怎么写

```ini
@mode = take
@default = 100

# 必选：数值越大越优先（确定性，不是随机）
tech_physics_1     = 101    # 量子计算
tech_society_1     = 101    # 异星生物学
tech_engineering_1 = 101    # 纳米力学

# 禁选：永远不选它（但只要还有别的可选，研究继续）
tech_colonial_centralization = 0    # 殖民集中

# 负数兜底：全部没有正数时才用，取数值最大的（-1 优于 -1000）
tech_mountain_range = -3    # 地表重塑
tech_volcano        = -7    # 地壳深部工程
```

### 语义速查

| 写法 | 含义 |
|---|---|
| `> 0` | 按数值取最大（**确定性**） |
| `= 0` | 禁选，永远不选 |
| `< 0` | 全部没有正数时，取**数值最大**的（-1 优于 -1000） |
| 没写 | 用 `@default`（默认 100，即按默认权重参与） |

### 并列怎么办

多个候选权重相同时，在并列者里**平均概率随机**选一个。

### 全禁会怎样

候选全是 `0` 时 → **停止该领域研究 + 关闭该领域的自动科研**。

只要有一个非 0，研究就继续。

## 看日志

日志在 `auto_research_weights.txt` 同目录的 `auto_research.log`。

### 三种关键记录

```
[PICK] 领域=物理 候选数=3 候选=[tech_a（中文名）,tech_b（中文名）,tech_c（中文名）] 抽中=1 选中=tech_b（中文名） 动作=接管（并列随机）
```

| 字段 | 含义 |
|---|---|
| `领域` | 物理 / 社会 / 工程 |
| `候选数` | 这次有几张卡 |
| `候选` | 候选列表（key + 中文名） |
| `抽中` | 随机落到的下标（0-based） |
| `选中` | 最终选了什么 |
| `动作` | 见下表 |

```
[TAKE] n=117 领域=工程 候选数=3 (正数=第2项/权重1000 负数=第-1项/0 可读=3 全禁=否) 动作=接管（唯一最优）
```

```
[汇总] 总决策=153 真选卡=153 早退=0 玩家=153 AI=0 | 并列=152 撞上原选=36 | [PICK] 接管=116 保留=37
```

**`[汇总]` 只在正常退出游戏时打一条。**

### 动作含义

| 动作 | 含义 |
|---|---|
| `接管（唯一最优）` | 有一个候选权重最高，选中它，改写了游戏选择 |
| `接管（并列随机）` | 多个并列最高，随机选一个，改写了游戏选择 |
| `接管（负数兜底）` | 没有正数，用负数兜底 |
| `接管（负数并列）` | 负数并列随机 |
| `★全禁→停研究` | 候选全是 0，停止研究 |
| `不干预（随机命中游戏原选）` | 随机抽到的恰好是游戏原选，实际没改 |
| `不干预（最优即游戏原选）` | 唯一最优恰好是游戏原选 |
| `不干预` | 无法判断，不干涉 |

### 日志多大

一局约 **80 KB / 550 行**。

里面 95% 是 `[PICK]` / `[TAKE]` 的真实数据，噪声已清理干净。

## 怎么判断生效了

### 接管生效

日志里出现：

```
动作=接管（并列随机）
```

**⇒ 说明真的改写了游戏选择。**

### 禁选生效

配置了 `tech_xxx = 0`，看它有没有被选中：

- `[PICK]` 的候选列表里出现它，但 `选中=` 从来不是它 → 生效
- 从来没出现在候选里 → 可能还没解锁

### 没生效

看日志有没有：

```
[cfg] reloaded: mode=take ...
```

- 如果 `mode=observe` → 你忘了改 `@mode`
- 如果这行都没出现 → DLL 没加载

## 排障

### DLL 装了但没反应

```
① 确认游戏版本是 4.5.4 (Cygnus)
   版本不对时 DLL 会拒绝加载（日志里有版本闸门提示）
   
② 确认日志文件有内容
   没有 → 注入器没加载成功
   
③ 看日志开头几行（banner）
   有 banner → DLL 加载了
```

### 配置改了但没生效

```
① 确认 @mode = take
② 确认保存了（热重载靠文件时间戳 + 大小变化触发）
③ 看日志 [cfg] reloaded 那行的时间戳是不是刚才
```

### 游戏崩了

日志里会有一段：

```
!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
!!! CRASH  code=0xC0000005
!!! crash addr = 0x...
!!! fault module = ...\stellaris.exe
!!! 请把这段发给开发者
!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
```

**把 `!!! CRASH` 到 `!!! 请把这段发给开发者` 之间的**所有行**完整复制，贴到 Issues。**

**⚠️ 注意区分：**
- `code=0xC0000005` / `0xC000001D` / `0xC00000FD` / `0xC0000409` / `0xC0000374` → **真崩溃**
- `[info] 软件异常 0x40010006` → 游戏正常控制流，**不是崩溃**

### 崩溃前发生了什么

如果你的 DLL 是**开发者版**，崩溃时会额外导出 200 条最近记录（环形缓冲），能看到崩前一刻在做什么。

## 配置文件格式

完整语法：

```ini
# 注释用 #

@mode = observe | take        # observe 只观察不接管；take 按配置接管
@default = <整数>              # 未列出的科技的权重（默认 100）

tech_xxx = <整数>              # 科技条目，可以写多个
```

**规则：**
- 指令名和值大小写不敏感（`@MODE = TAKE` 也行）
- 无效行会被跳过，不影响其他行
- 重复 key 后者覆盖前者
- **不写 `@mode` 就是 `observe`（安全默认）**

## 技术原理（给好奇的人）

游戏里自动科研是这样工作的：

```
每日 tick
  → 0x6F2590（玩家自动科研循环）
      → 检查该国家是不是玩家（country+0x314C != 0）
      → 对物理/社会/工程三个领域各调一次
      → 0x6F334E 处 CALL 0x820B30（选卡函数）
      → 选卡函数从候选池里挑一张卡
```

本 DLL 在 `0x6F334E` 处打了 9 字节的跳转 patch，把选卡函数的返回值**按配置改写**：

```
游戏选出 → 我们看一眼配置 → 选出我们想要的 → 返回给游戏
```

核心逻辑：

```
读候选池（slotmgr + (area+11)*0x18）
  → +0x08 是 tech 指针数组
  → +0x14 是数量

读每个 tech 的 key（tech + 0x20 的 std::string）
  → 查配置得到权重

决策：
  有正数 → 取最大（并列随机）
  无正数有负数 → 取数值最大的（并列随机）
  全 0 → 返回 nullptr，trampoline 检测到后跳到跳过装槽的路径
```

## 常见问题

**Q: 会不会影响 AI 国家？**
A: 不会。接管点是 `0x6F2590`，该函数入口检查 `country+0x314C != 0`（游戏自己的 `is_human` 判据），所以只对玩家执行。实测一局 153 次决策，`AI=0`。

**Q: 需要联网吗？**
A: 不需要。纯本地 DLL。

**Q: 支持多人游戏吗？**
A: 未测试。`is_human` 在多人下可能有不同语义。

**Q: 权重能写多大？**
A: 64 位整数范围内都行。实际只需要区分相对大小。

**Q: 能不能只让某个领域接管？**
A: 当前不支持。三个领域一起接管。

**Q: 日志里的「撞上原选」是什么意思？**
A: 并列随机时恰好抽到了游戏原本也要选的那个。此时实际没改写，但接管逻辑确实在工作。
